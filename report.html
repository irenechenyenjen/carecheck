1. Executive summary

CareCheck is an English-only web app for older adults who receive health tips through messages. A user pastes the message into one large input and selects Check this message. The app returns a plain-English classification, an explanation, a safer next step, and suggested sources.

The product is designed around a specific problem: forwarded health advice can sound confident and caring while omitting evidence, dosage, contraindications, or the need for professional care. CareCheck is intended as a pause-and-understand tool, not a diagnostic or treatment service.

Core promise: help a person understand what deserves caution before they believe or share a health message.

2. Problem and opportunity

Observed problem

The project began from a family observation: older relatives may trust health advice because it came from a friend, even when the message contains an implausible cure or encourages unsafe behavior. By the time another family member notices, the belief may already feel established.

Why existing experiences can fail this audience

  • Small text and dense screens increase effort.
  • Technical medical language can feel judgmental or confusing.
  • A binary “true/false” answer does not explain what to do next.
  • Requiring many controls or multiple screens can discourage use.

CareCheck addresses the interaction problem first: one clear action, large typography, high contrast, calm wording, and a result that explains uncertainty without shaming the user.

4. Product concept and scope

In scope

  • Paste a health message in English.
  • Run repeated checks without refreshing the page.
  • Receive one of five understandable categories.
  • See explanation, safer next step, and reading suggestions.
  • Use a deterministic fallback when the model service is unavailable.

Out of scope

  • Diagnosis, emergency triage, prescriptions, or treatment decisions.
  • Image/video analysis in this checkpoint.
  • Account creation, calendar integration, and personal medical records.
  • Guaranteeing that a source or model response is medically complete.

5. User experience and accessibility

The interface uses warm ivory, navy, terracotta, and slate tones. The layout keeps the main task visually dominant and avoids the earlier green/pink experiments. Controls are large and labeled with direct language: Paste a health tip here, Use an example, and Check this message.

The result language is conversational rather than sensational. For example, a broadly correct emergency instruction can be labeled “This is mostly correct, but let me tell you a bit more,” while a dangerous treatment claim receives “Be careful with this advice.”

6. AI design and classification

The app calls the configured OpenAI-compatible service through Portkey when a key is available, using gpt-5.6-luna. The model is instructed to return structured JSON with a level, summary, explanation, next step, sources, and tool name. The app normalizes common model labels to the five product categories.

CategoryMeaning
High cautionFalse, dangerous, or likely to cause harmful delay or treatment changes.
Mostly correctBroadly right but missing important context or a safety addition.
Looks usefulReasonable, low-risk advice supported at a general level.
Needs checkingPlausible or incomplete claim that should not be treated as established.
Unable to verifyInsufficient reliable evidence or too unusual to verify confidently.

A local fallback preserves basic behavior when the API is unavailable. Safety gates also prevent obvious hazards, such as contact with a decomposing animal carcass, from being downgraded by a variable model response.

7. Safety, limitations, and responsible use

  • CareCheck does not diagnose or replace a clinician.
  • Users with severe or sudden symptoms should seek urgent medical help.
  • Model output can be incomplete, mistaken, or poorly matched to an individual.
  • Sources and claims should be reviewed before making a high-stakes decision.
  • API keys are loaded from environment variables and are not stored in the interface.

The safest product behavior is to explain uncertainty and recommend an appropriate human next step, not to create false confidence.

8. Implementation

CareCheck is implemented as a Dash web app in app.py. Dependencies are listed in requirements.txt. Configuration is documented in .env.example; real secrets must remain outside version control. The app runs with debug mode disabled on localhost for the course demonstration.

Basic setup

  1. Create a virtual environment.
  2. Install requirements.txt.
  3. Copy .env.example to .env and add an authorized key if model calls are required.
  4. Run python app.py and open the local URL.

10. Reflection and future work

The main design lesson is that “simple” requires deliberate choices. Removing features can improve trust and usability when the audience needs a focused, predictable task. Another lesson is that AI classification needs a product-level safety layer: a model response alone is not enough for high-risk edge cases.

Future work could include source retrieval with citations, a clinician-reviewed knowledge base, multilingual support, a family-sharing workflow, and structured usability testing with older adults. Each addition would need privacy, accuracy, and accessibility review before inclusion.
